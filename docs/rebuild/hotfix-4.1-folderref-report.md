# Hotfix 4.1 — FolderRef stale-read reconciliation

Status: implementation complete; independent review pending.

## Bounded change

- Added additive `read_folderref_snapshot(rootPath, childPath)` through the existing generated IPC/documents/service/repository stack.
- The ordinary `read_file` command is unchanged.
- Backend canonicalizes the FolderRef root and nearest existing child ancestor, rejects symlink/reparse escape and containment violations, requires a regular case-insensitive `.md` file, and returns explicit retryable details only for absent/create-rename races.
- Frontend performs exactly four attempts (initial, 25ms, 75ms, 175ms) only for backend-classified retryable `stale_read` errors.
- A FolderRef selection flushes the current dirty document before starting the new task. Snapshot content and version token are committed once through `commitFolderRefSnapshot`; no follow-up `openFile`/`readFile` occurs.
- Readiness is ephemeral and keyed by collection/ref/normalized child path. Missing children remain disabled ghost rows with a structured Retry notice; successful events can retry the same intent. Selection/switch/dispose invalidates stale tasks and timers.
- Structured errors are formatted through `formatIpcError`, avoiding `[object Object]`.

## Synthetic evidence

Evidence is generated by `scripts/hotfix41/run-evidence.mjs` under ignored `artifacts/phase4/hotfix41/<run-id>/`. It uses only unique tempfile roots and redacts workspace/absolute paths from command output. No external/user path is read, logged, hashed, copied or captured by the hotfix tests.

Targeted coverage includes create-then-read, temp-to-final rename readiness, exact retry count, terminal containment/extension/directory/encoding errors, dirty-A save failure, structured notice and generated handler/contract checks.

## Limitations

- The hotfix intentionally supports Markdown FolderRef children only, as approved. JSON/non-Markdown classification remains separate unless added by a future approved plan.
- No Phase 5 workflow/UI redesign, metadata/schema/event architecture, or Cargo/dependency change is included.
