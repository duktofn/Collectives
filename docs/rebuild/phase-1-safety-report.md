# Phase 1 safety baseline

Phase 1 adds structured `SafetyError` command rejection, ZIP preflight quotas/path validation, explicit conflict resolution, scoped transaction journals/recovery, same-directory durable collection replacement, atomic group promotion, conditional editor snapshots, and `colorBody` settings compatibility.

The approved Phase 0 source is resolved by `scripts/phase1/resolve-phase0-evidence.mjs` from `artifacts/phase0/approved-manifest.json`; no timestamp path is embedded in the resolver. Phase 1 artifacts must retain `baseline-source.json`, reconciliation, journal state/evidence, before/after digests, and test logs.

Archive preflight rejects traversal, absolute/drive/NUL/invalid UTF-8/special members, duplicate IDs/members, invalid mappings, and quota violations before destination mutation. Import resolutions are complete and explicit; an empty or unknown resolution map is rejected when conflicts exist.

The current transaction journal is scoped to `collections_dir/.collectives-transactions/v1/<transaction-id>`, has explicit state transitions, and blocks unsafe mutation when recovery is pending. Recovery is deterministic after the recovery hook succeeds; an immediate crash boundary is not claimed to be byte-identical.

The journal persists the ownership marker, validated roots, cross-volume capability, fsync capability, backup manifest with before/after BLAKE3 digests, and per-operation status before a destructive rename. Unix journal writes use file `sync_all` plus directory fsync; Windows uses flushed files and the platform replacement path where a destination already exists. Cross-volume publication uses an owned sibling publish stage; an existing cross-volume destination uses an owned sibling backup stage before replacement. Recovery validates every marker/path, verifies committed final digests, restores `AssetsCommitting`/`MetadataCommitting`, removes only digest-owned new outputs, preserves and blocks `RollbackPending`, and keeps tampered ownership as a recoverable error.

Import stages a copy of the destination, applies overwrite/rename/skip resolutions there, rebases manifest paths, and publishes the staged directory only after the backup record is durable. ZIP and folder export prevalidate every source, stage complete output, record its final digest, and publish by owned rename/cross-volume copy; existing outputs are never deleted first. The injected unit seams cover ZIP extraction and folder copy failure, while persisted integration cases cover asset-commit failure, metadata-after-assets rollback, committed verification, rollback failure/blocking, path tampering, new-output cleanup, and cross-volume capability.

The editor keeps a pending selection until the current generation/revision save succeeds, coalesces concurrent save/close requests, rejects stale conditional writes, retains drafts on failure, and exposes explicit Retry, Close, and Reload and discard local draft actions. Selection transitions and window close are awaited/serialized; component tree handlers use the same async contract. The Rust integration suite currently reports 21 Phase 1 safety tests, and the frontend suite reports 67 tests.

The revisioned save queue now stores immutable `(path, generation, revision, content, expectedToken)` snapshots. An active write and queued snapshots are drained serially; a newer revision is written after the older write, receives the newly persisted token, and remains queued after an earlier failure. Close and file-switch operations await the complete drain. On Unix, transaction volume capability compares `st_dev` from the nearest existing path ancestor; unavailable metadata fails closed before journal/destructive work. Windows retains drive-volume detection, and the simulated sibling backup recovery remains covered.
